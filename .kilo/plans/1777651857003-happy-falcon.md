## 三、engine.js — `processEffects` 新增领域DoT跳字逻辑

位置：在 player buff 循环体内，`if (b.type === 'hot')` 块之后、`if (b.dur <= 0)` 清理之前。

逻辑伪代码：

```
如果 b.type === 'domain'：
    1. 烈焰领域叠层：每2秒 stackCount += 1（最多10层）
    2. DoT跳字：每秒一次
        a. 计算基础倍率 effectiveDps = b.dps
        b. 虚空领域阶梯增伤：怪物血量50%~30% → ×1.5；<30% → ×2.0
        c. 烈焰领域层数增伤：× (1 + 0.1 × stackCount)
        d. 死亡领域负面计数：怪物身上 dot/vuln/debuff 数量 × 0.15 加成
        e. 用 calcDmg 计算最终伤害
        f. 扣减怪物血量
        g. 圣光领域吸血：HP>50% → 回复5%伤害；HP<50% → 回复10%伤害
        h. 圣光吸血额也需检查海洋受疗加成（×1.2）
        i. 输出日志
```

### 具体代码

在 `processEffects` 中 player buffs 循环的 hot 处理块下方插入：

```javascript
// ===== 领域技持续伤害 =====
if (b.type === 'domain') {
    // 烈焰领域：每2秒叠1层
    if (b.domainType === 'flame') {
        b.stackTimer = (b.stackTimer || 0) + deltaTime;
        if (b.stackTimer >= 2000 && (b.stackCount || 0) < 10) {
            b.stackCount = (b.stackCount || 0) + 1;
            b.stackTimer -= 2000;
        }
    }

    // 每秒一次DoT跳字
    b.tickTimer = (b.tickTimer || 0) + deltaTime;
    if (b.tickTimer >= 1000) {
        b.tickTimer -= 1000;
        let effectiveDps = b.dps;

        // 虚空领域：血量阶梯增伤
        if (b.domainType === 'void') {
            let hpPct = (this.mob.hp / this.mob.maxHp) * 100;
            if (hpPct <= 30)      effectiveDps *= 2.0;
            else if (hpPct <= 50) effectiveDps *= 1.5;
        }

        // 烈焰领域：层数增伤
        if (b.domainType === 'flame') {
            effectiveDps *= (1 + 0.1 * (b.stackCount || 0));
        }

        // 死亡领域：怪物负面效果计数增伤
        if (b.domainType === 'death') {
            let negCount = 0;
            this.mob.buffs.forEach(mb => {
                if (mb.type === 'dot' || mb.type === 'vuln' || mb.type === 'debuff') {
                    negCount++;
                }
            });
            effectiveDps *= (1 + 0.15 * negCount);
        }

        // 计算易伤乘区
        let vulnMult = 1.0;
        this.mob.buffs.forEach(mb => { if (mb.type === 'vuln') vulnMult *= mb.val; });

        let res = this.calcDmg(effectiveDps, vulnMult);
        this.mob.hp -= res.val;
        let dotLogMsg = `${b.stateEmoji} [${b.stateName}] 造成 ${formatNumber(res.val)} 点伤害`;
        if (res.isCrit) dotLogMsg += ' (暴击!)';

        // 圣光领域：吸血
        if (b.domainType === 'holy') {
            let hpPct = (this.player.hp / this.player.getMaxHp()) * 100;
            let lifestealRate = hpPct < 50 ? 0.10 : 0.05;
            let healAmt = Math.floor(res.val * lifestealRate);
            // 海洋领域受疗加成（虽不能同时存在，但遵循统一规则）
            if (this.player.buffs.some(pb => pb.type === 'domain' && pb.domainType === 'ocean')) {
                healAmt = Math.floor(healAmt * 1.2);
            }
            this.player.hp = Math.min(this.player.getMaxHp(), this.player.hp + healAmt);
            dotLogMsg += `，回复 ${formatNumber(healAmt)} 点生命`;
        }

        this.log(dotLogMsg, 'sys');
    }
}
```

### 2.6 `parseSequenceText()` — 解析 `!` 前缀

位置：`js/ui.js:1481`

在现有 `@` 前缀解析逻辑中，同时检查 `!` 前缀。修改返回值为 `{ ids, openers, bossOnlyIds }`。

解析规则：
1. 去除行首空白
2. 检测 `#` 注释 → 忽略
3. 检测 `!` 前缀（可能在 `@` 之前或之后）→ 标记为 bossOnly
4. 检测 `@` 前缀 → 标记为 opener
5. 剩余文本 → 技能名匹配

处理示例：
- `!阿赖耶识·斩` → ids + bossOnlyIds
- `@ !阿赖耶识·斩` → ids + openers + bossOnlyIds
- `!@ 阿赖耶识·斩` → ids + openers + bossOnlyIds
- `@ 魔力弹` → ids + openers

**简化方案**（推荐）：先检查行首是否有 `!`（连续处理，strip掉所有前导的 `!` 和 `@`），用一个循环来提取所有前缀标记。这样可以处理任意顺序：
```javascript
let isBossOnly = false;
let isOpener = false;
let remaining = trimmed;
// 循环处理前缀标记
while (remaining.startsWith('!') || remaining.startsWith('@')) {
    if (remaining.startsWith('!')) {
        isBossOnly = true;
        remaining = remaining.substring(1);
    }
    if (remaining.startsWith('@')) {
        isOpener = true;
        remaining = remaining.substring(1);
    }
}
let skillName = remaining.trim();
```

返回值扩展为：
```javascript
return { ids, openers, bossOnlyIds };
```

# Bug修复：parseSequenceText 前缀解析失败

## 问题现象

导入含 `@!技能名` 或 `!@技能名` 的序列文件时，前缀未能正确解析。表现为：
- 全角感叹号 `！` 不被识别为 bossOnly 标记
- 前缀字符间有空格时解析中断（如 `@ ! 技能名`）
- 导致技能名匹配错误，技能被替换为其他技能

## 根因

当前 `parseSequenceText` 的前缀解析使用 `while (remaining.startsWith('!') || remaining.startsWith('@'))` 方式：
1. 只识别半角 `!`（U+0021），不识别全角 `！`（U+FF01）
2. 移除一个字符后直接用 `substring(1)`，不自动跳过后续空格，导致 `@ !` 中的 `!` 在空格后无法被下一轮识别

## 修复方案

将前缀提取逻辑改为逐字符检测 + `trimStart()` 模式：

```javascript
let isOpener = false;
let isBossOnly = false;
let remaining = trimmed;
// 🔒 循环去除前导的 !/@ 标记（兼容半角全角感叹号，自动消费紧随空格）
while (remaining.length > 0) {
    let ch = remaining.charAt(0);
    if (ch === '!' || ch === '！') {
        isBossOnly = true;
        remaining = remaining.substring(1).trimStart();
    } else if (ch === '@') {
        isOpener = true;
        remaining = remaining.substring(1).trimStart();
    } else {
        break;
    }
}
let skillName = remaining;
```

**改动范围**：仅 `js/ui.js` 的 `parseSequenceText` 方法中前缀解析段（约第 1520-1535 行），约 10 行代码替换。

- [ ] `@ ! 法则解构` → isOpener=true, isBossOnly=true, skillName="法则解构"（前导空格被自动消费）
